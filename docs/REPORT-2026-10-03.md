# Response to the 2026-10-03 technical report

Every item in the report, what was done about it, and where to look.
Version `0.6.0`.

## Sprint 1 — P0 (user-facing breakage)

### 2.1 The Termux extra-keys row

**Was:** the installer wrote `extra-keys = []` into
`~/.termux/termux.properties`, which hides the ESC/CTRL/arrows row —
on a phone that removes the only way to send Ctrl-C. `use-black-ui`
was imposed too.

**Now** (`src/components/setup_launcher.sh`):

- An existing `extra-keys` line is never touched.
- If there is no row at all, a usable two-row default is written
  (ESC/CTRL/ALT/TAB/arrows, `/`, `-`, `|`, HOME/END/PGUP/PGDN).
  Override with `TDE_TERMUX_EXTRA_KEYS`.
- A row left as `[]` by an older version is *reported*, with the fix
  (delete the line, run `archreapply`), rather than silently kept or
  silently overwritten — the installer cannot tell your choice from its
  own old bug.
- `use-black-ui` is opt-in: `TDE_TERMUX_BLACK_UI=1`.
- `phase3_launcher_ok` no longer demands an extra-keys line exists.

While testing this, a real latent bug surfaced and was fixed: a missing
`termux-reload-settings` made the function return non-zero as its last
statement, which under `set -e` aborted the whole installer.

### 2.2 Nerd Font install and verification

**Was:** `>100 KB` was the whole definition of "the font installed",
one attempt, and no explanation when icons stayed as boxes.

**Now** (`src/components/nerdfonts.sh`, `src/lib/verify_functional.sh`):

- `nerdfont_file_ok` requires size **and** TTF/OTF magic bytes
  (`00010000`, `OTTO`, `true`, `ttcf`). `phase5_nerdfont_ok` delegates
  to it.
- The whole pacman→zip chain retries `TDE_NERDFONT_ATTEMPTS` (3) times,
  driven by re-validating the *file* rather than trusting an exit code.
- The font is staged to `font.ttf.tmp` and only moved into place once
  valid, so a failed attempt never leaves a broken `font.ttf`.
- An already-valid font short-circuits the whole step.
- Success prints the force-stop instruction (Android caches the font
  per app, so a settings reload is sometimes not enough); failure names
  the attempt count and points at `archfont`.
- New `archfont` command reinstalls and validates on demand.

### 2.3 / 3.4 Launcher smoke test

**Was:** `proot-distro login ... -- true`, no timeout. A container that
booted but had no working user still passed, and the snippet then
`exec`'d into it — leaving no way back into Termux.

**Now:** the check verifies the home directory exists, `/usr/bin/zsh`
is executable, and the user's login shell really is `/usr/bin/zsh`, all
under `timeout ${TDE_LAUNCHER_SMOKE_TIMEOUT:-25}`. On failure you stay
in Termux with a message that distinguishes a timeout (container
unresponsive → `archkill`) from a failed check, and points at
`archdiag` / `archhealth` / `TDE_SKIP_LAUNCHER=1 zsh`. Phase 6
re-asserts the snippet at the end of every install.

A bug was caught by the test while writing this: the first version let
the *Termux* shell expand `$HOME` and `$(getent …)` at install time,
baking Termux's own values into a check meant to run inside Arch — it
would have refused to ever enter the container.

### 2.4 fastfetch banner

`printf '\033c'` before `fastfetch` in the container `.zshrc`, so the
banner is not printed under the previous session's scrollback.

## Sprint 2 — P1 (robustness)

| Item | Resolution |
|---|---|
| 3.1 Telecom | Still opt-in, no longer silent: an interactive run asks once (default **No**) and records the answer; non-interactive runs skip with a visible warning naming `TDE_WITH_TELECOM=1`. `TDE_SKIP_TELECOM=1` never asks. The audit and self-heal read the recorded answer and never prompt. |
| 3.2 Lock file | Stores the holder's PID; a refused run names it and offers `kill <pid>`, or the exact `rm -f` when the recorded process is gone. Never breaks a lock automatically. |
| 3.3 `--env` content | `idempotent_append_container` pipes the block in on stdin instead of a single environment variable (which caps out around 128 KB), with an empty-stdin guard so a failed transfer cannot blank an existing block. |
| 3.5 HTTPS rootfs | Already done in `27d06b2` (https first, http fallback per mirror). |
| 3.6 Phase 5 | A WARNING-level audit failure records `PHASE5_WARNINGS`, which keeps Phase 5 eligible to self-heal on the next run (`TDE_NO_SELF_HEAL=1` opts out). `archselfheal` runs self-heal + audit on demand. |

Two real bugs were found while testing the lock change, both of which
had been silently breaking error reporting:

- `exec {fd}>"$file" 2>/dev/null` redirects the **shell's** stderr
  permanently, not the redirection's — every later error message
  (including the lock's own) was going to `/dev/null`.
- Opening the lock with `>` truncates the file at `open()`, before
  `flock` is attempted, so a second process wiped the holder's PID on
  its way to an error that then could not name it. Now opened `>>`.

## Section 6 — restructure

`core.sh`, `lib/` and `components/` now live under `src/`. The root
`core.sh` is a three-line launcher that `exec`s `src/core.sh`, so every
documented command and every generated script that references
`./core.sh` keeps working. Phase 6 still installs a flat
`lib/` + `components/` into `$PREFIX/share/termux-dev-env`, so the
`arch*` commands are unaffected by the repository layout. Tests point
`SCRIPT_DIR` at `src/`; `TDE_PROJECT_ROOT` covers `VERSION` and `docs/`.

## Section 8 — the acceptance checklist

What can be verified off-device is verified automatically:
`tests/verify_all.sh` is clean, with **232** unit checks, including 84
new ones written for this report (`tests/cases/36-*.sh`, `37-*.sh`).
Round 8 runs a full `--dry-run` of the installer and of each
`--reinstall` phase.

The remainder of the checklist is inherently on-device — a real
install, the keyboard row, the font rendering after a force-stop, the
first `nvim` launch. Each of those now has either a command
(`archhealth`, `archselfheal`, `archfont`, `archparu`) or a
TROUBLESHOOTING entry attached to it.
